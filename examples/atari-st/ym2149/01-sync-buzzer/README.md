# YM2149：R13再トリガーのSync-buzzer実験

公開npm `tetorica-fm2612@0.2.41` から、YM2149をAudioWorkletへ接続するWeb専用例です。ローカルのTetorica本体には依存しません。元のゲーム曲やサンプルは使いません。

一覧からWebを開き、Playを押します。初期メロディは8拍で終了します。コード欄を書き換えて次のPlayで試せます。ページの読み込みだけではAudioContextを作りません。Stopは予約をキャンセルし、最後のVolumeを0にしてエンドポイントとAudioContextを解放します。読み込み途中のStop・実行エラー・pagehideでも同じ後片付けを行います。

## 何がハードウェアの機能か

YM2149のR11／R12は共有EnvelopeのPeriod、R13はShapeです。同じ値のR13を書き直してもEnvelopeが再開始します。この例はShape 8を110回/秒で書きます。個々の書き込みはAudioWorkletのサンプル時計に予約し、JavaScriptのタイマーから毎回送信しません。

予約するタイミングはソフトウェアの処理です。音量の32段階EnvelopeとToneの生成はYM2149の機能です。Atari STのCPU／MFPタイマーをエミュレートしたり、過去の全Sync-buzzer奏法を正確に復元したりする例ではありません。

`type:0x10` がYM2149、入力クロックは2,000,000 Hz、`flags:1` を使います。`type:0` は別のAY-3-8910モデルです。モデル設定はエンドポイントとクライアントへ同じ値を渡します。

## 変えてみる

- `setBpm(120)`：メロディと休符の長さを変えます。`beat(0.4)`と`beat(0.1)`で1音が0.5拍です。
- `retriggerHz`：R13再トリガーの周期を変えます。BPMとは独立したHzです。
- `period:100`：自然なEnvelopeの速さを変えます。この設定では2 MHz／256／100＝78.125 Hz、12.8 msで32段階の下降が1回です。R13を110回/秒で書くと約9.09 msごとにShapeを再開始します。
- `tone:false`、`noise:false`を保って`envelope:true`：Toneの音程を除いてEnvelopeの動きを聴く実験になります。Envelope有効時には固定Volume値で別の強さを設定しません。

物理CH1はAPIでは`0`です。Envelopeは3CH共通なので、R13の書き込みはすべてのEnvelope使用CHへ影響します。

## 記録・予測・実行

`build(b => ...)` はコールバックを一度だけ呼び、操作と時刻をデータにします。ライブ状態を読み取ったり、音源を変えたりしません。`atSample(0)`は予約開始からの絶対オフセットです。基準サンプルレートはデフォルト44100 Hzで、出力機器のレートに依存しません。

`compile(...,{initialState:"client"})` はローカルの状態を基準にR13の書き込みを予測します。表は操作による書き込みだけを表示し、同じ値への再書き込みを省略しません。予定に別の手動操作が割り込んだときの実行履歴とは別です。

`schedule(...,{name:"sync-buzzer",repeatSeconds:1/retriggerHz})` のPromiseは予約の受付で解決します。名前の再使用は古い予約を置き換えて位相を再開始します。`clearSchedule()`は未来の書き込みを取り消し、適用済みのレジスタ値は元へ戻しません。この例は終了時に明示的にKey Offも行います。

Nativeのtimed実行は今回の公開APIでは未対応です。この例はNodeの壁時計タイマーへ置き換えず、ブラウザー専用として掲載しています。
