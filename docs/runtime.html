TETORICA-FM2612 · RUNTIME GUIDE

Runtime の構成と選び方

公開済み npm package のどの API を使うか、アプリ・ゲームへの組み込み方に合わせて選びます。

npm install tetorica-fm2612

チップ別の基本例（npm 0.2.6）

Web: createSoundChip(name, {execution: 'worklet'})
     → WorkletTransport → Synth（Main）→ WASM（Worklet）
Node: createSoundChip(name)
      → AudifyTransport → Synth / WASM（呼び出し元）→ 音声出力

演奏するコードは同じ Synth の API。DirectTransport の PCM / WAV 手順は専用例へ分けています。 MegaSynth はゲームへの埋め込み用の統合 API として別枠に残しています。

FM 発音 · DirectTransport の PCM / WAV

音源を直接操作する

generated/*.js + *.wasm  チップのエミュレーター
          ↓
createSoundChip()        レジスタ・PCM 生成の入口
          ↓
DirectTransport         synth の命令を chip に渡す
          ↓
YM2612Synth など         noteOn / preset / operator
          ↓
generateStereo(frames)   時間を進めて Float32 PCM を生成
          ↓
Web Audio / encodeWav()  ブラウザ再生 / Web・Node の WAV 保存

generateStereo() を呼ぶとチップの時間が進みます。Node では AudioContext や音声ドライバーは不要です。 createSoundChip('ym2612') は Web / Node に応じて WASM を自動読み込みします。

DirectTransport の PCM 生成 · レジスタ直接操作 · PCM / WAV 出力

リアルタイムで組み込む

YM2612WorkletTransport は synth の命令を AudioWorklet へ送り、音声スレッドで PCM を生成します。 processor の読み込み、WASM の転送、ready 待機を自分で扱う例が AudioWorklet の最小例です。

MegaSynthは、その初期化と終了、FM、Web Audio の FX、イベント録音をまとめます。 start() 後に fm を操作し、終了時は close() を呼びます。

発音 + delay / reverb · イベント JSON の録音・再生 · 音符の looper

Playground は liveLoop・play・beat を含むコードを実行します。 load() → play(name, {execution: 'worker'}) でゲームの UI と演奏コードを別スレッドに置けます。 stop() は演奏停止、finalize() は Worker・音声リソースの解放です。

Playground Runtime を組み込む

VGM と音色ファイル

VgmPlayer は VGM のコマンドと待ち時間を処理し、GenesisAudioEngine が YM2612 + Sega PSG の PCM を生成します。 VgmRuntime はブラウザの読み込み・再生・一時停止・停止・音声出力をまとめます。 VGM の出力 Worklet は生成済み PCM を再生する方式です。チップを音声スレッドで動かす synth Worklet とは役割が異なります。

VGM 再生（Web / Node）

tfi.js と vgi.js は音色バイナリを logical preset に変換します。 operator 番号は 1〜4。fm.setPreset() に渡して発音し、同じ形式へ export できます。

TFI import / export · VGI import / export

ブラウザでの配置と実行環境

この examples は import map で tetorica-fm2612 の bare import を、コピーした npm package へ解決します。 npm run dev と npm run build が package の JS・WASM・Worker・Worklet・ライセンスを vendor に配置します。 自分のアプリでも package 内の相対配置を保ち、runtimeAssetUrl() で必要なアセットの URL を取得します。

個別の Sega PSG・Game Boy・OKIM6258 ラッパーや VgmRuntime は、生成済みローダーと WASM バイト列を渡す API を使います。 MegaSynth / Playground は Worklet と WASM の URL を指定します。具体的な手順は各例のソースに省略せず記載しています。

ブラウザでは HTTP サーバーで配信し、AudioWorklet は HTTPS または localhost で実行します。 音声は Play などのユーザー操作から開始します。Node は22以降に対応します。 Web Audio を使う埋め込み例は Web 専用、PCM 生成・WAV 出力・音色変換は Node でも実行できます。

npm run build の dist/ を静的ホストに配置できます。GitHub Pages の repository 配下でも相対 URL で動作します。

配布物には RUNTIME.md、soundchip.md、runtime-manifest.json、 THIRD_PARTY_LICENSES.txt、licenses/、sources/ が含まれます。 Package の説明・APIも参照してください。
